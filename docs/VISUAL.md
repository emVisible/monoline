# 视觉要素清单与实现方式（对标 PPT 级动效视频）

这份文档回答一个问题：让人觉得「这是专业团队做的动效视频」的画面，到底由哪些
要素构成；Monoline 现在有哪些、缺哪些、用什么方式补。写法上每一条都要能落到
一个具体的 CSS 类 / 模板 / 函数上，不写「更有质感」这类无法验收的话。

参考对象：企业发布会字幕片、Keynote / PowerPoint 高级模板、Gemini/Anthropic 模型
发布片、Beamer→Streamline 那类技术讲解片。共同点不是「炫」，而是**同一套几何规则
反复出现**——这就是「设计感」的可复制来源。

## 2. 三条实现原则（V31 期间被验证或被违反后修正）

**a. 一切几何在 compose 期算完。** 渲染器并行采样帧，任何 `getBoundingClientRect()`
或运行时测量都会错位。所以 `polar()` / `funnel_widths()` / `stack_widths()` /
`sparkline()` 全部返回静态标记，浮点统一 round 到 2 位——同输入必同字节。

**b. 单色语言优先于「好看」。** 涨跌用 accent / ink-muted + 箭头形状区分，不用红绿；
donut 四段用 ink 的四个透明度档位，而不是四种颜色。加颜色的冲动，99% 是在补设计
的缺。

**c. 缺数据就什么都不画。** `sparkline()` 少于两个真实数字返回 `''`；`delta()` 读不出
方向返回 `None`。第一版把 `"1.2 / 1.9 / 2.4"` 当字符串逐字符解析，抽帧里画出了一条
锯齿假线——假图比没图严重。

    - **11a（真缺陷，范围小）— 已做 `b366657`**：只拦形态确定的——纯 URL、`链接：` 前缀、「…转载…出处」
      类自指句。三条硬特征，本轮实测误杀 0/164。
    - **11b（更要紧，未做）**：长句被劈成两拍时后一拍以「，」「、」结尾，画面会把一个
      从句当完整观点打成大字号。**规模已量（155 拍，已再剔开发稿）：15 拍 = 9.7%

      「君王将宫殿修得越来越高，在彰显国力、君威的同时，」「他们也自知…变得越加冷清、
      孤寂，让孤、寡、不穀、」「【余承东回应问界调整：…】9月24日，」。
      要查 `segmenter._split_long` 在 40 字上限下是否宁可截断也不换行/合并，以及这类拍
      该不该并进同一场景当第二行（IR 是 1 拍↔1 场景，所以更可能是「同一场景两行」）。
10. **同一份稿子两次跑，分镜结果不一样——已定位到两个独立缺陷。**
    2026-09-05→25 用同一条 15 行文稿连跑，作业 `001a0d863e3f57beb236550` 留下两行 plan：

    ```
    v1 source=llm   title statement flow list steps statement kpi definition list section statement statement steps summary
    v2 source=rules title statement statement list statement statement kpi statement list section statement statement statement summary
    ```

    两次 events 都记到同一个模型（`分镜判定：batiai/gemma4-e4b:q4`），也就是 **target.ok
    两次都成立、upgrade 两次都真的跑了**，但第二次 `llm["upgraded"]` 为空，于是 source 落回
    rules、四类升格（flow / steps×2 / definition）全部退回 statement。

    - **缺陷 A：LLM 升格不可复现。** `planner.upgrade()` 已经是 `temperature=0.0`，
      本地量化小模型仍给不出稳定结果。这不是采样温度能修的。
    - **缺陷 B：~~resume 会用更差的 plan 静默覆盖更好的~~ 已修（`ed8d666`）。**
      `keep_richer_plan()` 判一次：本次没有升格（rules/manual 等非 llm 来源）而库里已存
      `source='llm'` 的 plan，就沿用旧版、同步 `ir/scene_plan.json`、记一条 warn，不再写
      新行。首跑与「这次真的又升格了」两条路径不变。5 个分支各有断言，80 passed，
      warmup 端到端 18.3s 正常出片。

    先修 B：plan 阶段若本次 `upgraded` 为空而该作业已存在 `source='llm'` 的 plan，就沿用
    旧版本并记一条 warn，而不是覆盖。A 需要的是把升格结果按 (script_hash, model) 落盘复用
    ——同一个 job 内已经天然复用（DB 里那份），跨 job 才谈得上「同样的文字同样的片子」。

> **数字上屏的原则（V39 补）**：一个数字被放大成 hero 之前，先问它是不是**量级**。序数
> （第10句）、约数（40多岁）、以及会把残留量词丢进标签的数量（7个案例 → 「 个案例」）
> 都不是。把它们放到 200px，等于替文稿宣称一个它没说过的数字。

   同一次测量给出的下一步依据：**statement 119/236 = 50.4%，stat 73 = 30.9%**，statement
   标题中位 10 字、只有 9% 含逗号（所以「按从句分句做层级」覆盖不到 10%）。因此 V38 选择
   给文字版面加**结构骨架**而不是继续加分句规则。

> **方法记录（V35）**：上面 6、7 以及四个已修缺陷（假趋势、枚举吞项、孤儿折行、切坏的
> KPI 标签）都是**逐拍抽帧**看出来的——拿一段 15 行真实文稿跑完整管线，在每拍停留时长
> 的 80% 处取一帧拼成 contact sheet 一次看完。单测能证明分类对，证明不了「这一屏好不好
> 看」；只看一帧也看不出「连续十帧长一个样」。
