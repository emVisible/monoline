# 视觉要素清单与实现方式（对标 PPT 级动效视频）

这份文档回答一个问题：让人觉得「这是专业团队做的动效视频」的画面，到底由哪些
要素构成；Monoline 现在有哪些、缺哪些、用什么方式补。写法上每一条都要能落到
一个具体的 CSS 类 / 模板 / 函数上，不写「更有质感」这类无法验收的话。

参考对象：企业发布会字幕片、Keynote / PowerPoint 高级模板、Gemini/Anthropic 模型
发布片、Beamer→Streamline 那类技术讲解片。共同点不是「炫」，而是**同一套几何规则
反复出现**——这就是「设计感」的可复制来源。

## 1. 要素清单

| 13 | 字幕版式 | 字幕不是第二份正文 | 三种 preset 下的下三分之一/描边/色块 | 已有（V13） |

## 2. 三条实现原则（V31 期间被验证或被违反后修正）

**a. 一切几何在 compose 期算完。** 渲染器并行采样帧，任何 `getBoundingClientRect()`
或运行时测量都会错位。所以 `polar()` / `funnel_widths()` / `stack_widths()` /
`sparkline()` 全部返回静态标记，浮点统一 round 到 2 位——同输入必同字节。

**b. 单色语言优先于「好看」。** 涨跌用 accent / ink-muted + 箭头形状区分，不用红绿；
donut 四段用 ink 的四个透明度档位，而不是四种颜色。加颜色的冲动，99% 是在补设计
的缺。

**c. 缺数据就什么都不画。** `sparkline()` 少于两个真实数字返回 `''`；`delta()` 读不出
方向返回 `None`。第一版把 `"1.2 / 1.9 / 2.4"` 当字符串逐字符解析，抽帧里画出了一条
锯齿假线——假图比没图严重。

## 3. 还缺什么（下一批）

1. ~~**matrix（2×2 象限）**~~ 已交付（V31f）：判据收紧为「明确出现象限/矩阵/二维定位」
   且正好四格，坐标轴只在文稿说了才画。
2. **多拍归组**：现在 1 拍 ↔ 1 段 ↔ 1 场景是硬约束，所以一段 markdown 表格会被切碎。
3. **词级字幕**：需要云 TTS 的 word timestamp，本地 Kokoro 拿不到。
4. ~~**动效密度自适应**~~ 已交付（V34）：`stagger: { amount }` 由 `seg.dur` 算出，
   夹在 `[0.22, 2.6]`，并保证最后一项在转场前落定。
5. ~~**图形 kind 的覆盖率**~~ 已量（2026-09-25，26 条真实文稿 / 212 拍，剔除合成测试稿）：
   **图形/数据类只占 13.7%，纯文字占 86.3%，其中 statement 独占 57.1%。**
   statement 标题中位长度 10 字，含数字仅 2%、含引号术语 6%——所以「给关键词上色」
   这类结构性强调覆盖不到什么，缺的是**版式骨架**。V31g 因此给三种文字 kind 加了
   统一的 accent 竖轨。下一步同方向：让 statement 在长旁白下自动升格成
   definition / quote / list 等更有形态的布局（而不是继续加新 kind）。

   新 kind 在真实文稿上的命中：bars 1、kpi 2、timeline 3、share 2、trend 3、matrix 0
   （matrix 判据要求显式「象限/矩阵」词，0 命中是预期内的保守结果）。

6. ~~**逗号并列没被当列表**~~ **量过，暂不做**（2026-09-25，43 个真实作业 / 236 个去重节拍）：
   按「≥3 段短并列」粗筛出 12 拍，逐条看下来全是叙事散文的顺带逗号——「后来媳妇去健身房
   找我，跟她聊天，我才知道…」这类。把它们变成项目符号是错的。这正是 V31d 假漏斗的同一个
   失败模式。真要补，判据必须锁在冒号引导上，而锁完之后全语料只剩 1 拍，不值得动规则。
7. ~~**两节点流程图太稀**~~ **量过，不做**：同一语料里 flow/radial/steps 节点数 ≤2 的节拍
   **0 个**。那个孤悬的两胶囊来自我的一条测试稿。
8. ~~**多数字拍的「结论数」丢了**~~ **量过，不做**：含 ≥2 个数字的节拍占 7.9%，其中单位
   不一致的占这类 32%（全体 2.5%）；再往下看，去重后**只有 2 个不同句子**，且都是我自己
   写的测试稿。为两句合成文本定「哪个数字是被断言的」启发式，就是闭门造车。等真实用户
   稿攒够再回来看。

   同一次测量给出的下一步依据：**statement 119/236 = 50.4%，stat 73 = 30.9%**，statement
   标题中位 10 字、只有 9% 含逗号（所以「按从句分句做层级」覆盖不到 10%）。因此 V38 选择
   给文字版面加**结构骨架**而不是继续加分句规则。

> **方法记录（V35）**：上面 6、7 以及四个已修缺陷（假趋势、枚举吞项、孤儿折行、切坏的
> KPI 标签）都是**逐拍抽帧**看出来的——拿一段 15 行真实文稿跑完整管线，在每拍停留时长
> 的 80% 处取一帧拼成 contact sheet 一次看完。单测能证明分类对，证明不了「这一屏好不好
> 看」；只看一帧也看不出「连续十帧长一个样」。
